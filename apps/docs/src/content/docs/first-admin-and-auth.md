# First Admin And Authentication

## Bootstrap Admin

When no active admin exists, Arkivra promotes the oldest registered user to `admin` the next time that user reaches an authenticated API route. For a fresh deployment, the practical flow is:

1. Start Arkivra.
2. Open the dashboard.
3. Register the first account.
4. Sign in and load the app.
5. The account becomes the bootstrap admin.

After the first admin exists, other users remain regular members unless an admin invites or promotes them.

## Registration And Invitations

`ARKIVRA_AUTH_REGISTRATION_ENABLED` controls open registration. If registration is disabled and users already exist, new signups require an email invitation.

Admins can create account invitations from the dashboard admin area. Vault owners and admins can also invite vault members, depending on the flow and approval requirements.

## Email Delivery

Local development defaults to console email delivery:

```bash
ARKIVRA_EMAIL_DELIVERY=console
```

Production should use SMTP:

```bash
ARKIVRA_EMAIL_DELIVERY=smtp
ARKIVRA_EMAIL_FROM=noreply@example.com
ARKIVRA_SMTP_HOST=smtp.example.com
ARKIVRA_SMTP_PORT=587
ARKIVRA_SMTP_SECURE=false
ARKIVRA_SMTP_STARTTLS=true
ARKIVRA_SMTP_USER=<username>
ARKIVRA_SMTP_PASSWORD=<password>
```

## OAuth

Google and GitHub OAuth are optional. Configure the provider client ID, client secret, and callback URL only when you want that provider enabled.

For the default local API URL, callbacks are:

- Google: `http://localhost:1221/api/auth/callback/google`
- GitHub: `http://localhost:1221/api/auth/callback/github`

For production, the callback origin must match `BETTER_AUTH_URL`.

## Two-Factor Authentication

Users can configure TOTP two-factor authentication from security settings. Backup codes are generated by Arkivra and should be stored by the user. Operators should not rely on the database alone as an account recovery mechanism.
