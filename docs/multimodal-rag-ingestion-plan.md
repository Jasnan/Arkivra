# Multimodal Retrieval and Citation Plan

This document replaces the earlier multimodal RAG ingestion plan. The older
plan assumed local-only Ollama inference and embedding generation during
document ingestion. Those assumptions are no longer valid.

The current source of truth for the AI lifecycle is
[`ai-optional-indexing-architecture.md`](./ai-optional-indexing-architecture.md).
Use this document only for multimodal retrieval and citation follow-up work.

## Current Invariants

- Document ingestion is AI-optional. Upload, parsing, canonical persistence,
  document management, and full-text search must work with PostgreSQL and
  Docling only.
- Ingestion must not require an embedding provider, chat provider, Ollama, or
  any cloud model.
- Embeddings are generated by the embedding indexing subsystem after canonical
  chunks exist. They are not generated inside `persistParsedDocument`.
- Chunk vectors live in `document_chunk_embeddings`, scoped by
  `embedding_indexes`. Do not write vectors to `document_chunks.embedding`.
- Search and chat read vectors through the active embedding index. If no active
  index exists, retrieval falls back to full-text search.
- AI providers are provider-neutral at the service boundary. Ollama is the
  currently wired adapter, not an architectural constraint.
- Chat configuration and embedding index configuration are separate. Changing
  chat settings must not create, invalidate, or rebuild embedding indexes.
- Vault scoping is mandatory for every query, route, and asset access.

## What Remains Useful From The Old Plan

The product goals still apply:

- Preserve citation-grade provenance for chunks, including page numbers,
  bounding boxes, source element ids, original text, table HTML, and image
  references.
- Store source files and derived chunk assets through the existing storage and
  encryption paths.
- Return retrieval results with enough citation metadata for the web app to
  highlight document pages and render referenced assets.
- Keep full-text retrieval available even when AI is disabled or unavailable.

The implementation constraints have changed:

- Do not couple multimodal summaries or embeddings to the ingestion success
  path.
- Do not assume Ollama-specific settings in storage schemas or route
  contracts.
- Do not introduce a second vector datastore. PostgreSQL and pgvector remain
  the storage backend for embedding indexes.

## Follow-Up Work

### 1. Provenance Preservation

Extend parser output and chunk persistence so each chunk can carry:

- `page_start` and `page_end`
- bounding boxes
- source element ids
- parent element id
- original text
- table HTML
- citation precision

Backfill existing chunks conservatively. If provenance is unavailable, mark the
chunk as document-level citation precision and fall back to the canonical chunk
content.

### 2. Chunk Asset Storage

Add a `document_chunk_assets` table for image and table assets referenced by
chunks. Bytes should remain in the existing storage driver and use the existing
encryption path. PostgreSQL rows should store metadata and references, not
large base64 payloads.

Required access rules:

- Asset reads must join through chunk, document, and vault membership.
- Deleted documents must not expose assets.
- Asset routes must preserve the same authorization boundaries as document
  routes.

### 3. Optional AI Enrichment

Multimodal summaries can improve retrieval quality, but they must be optional.
If implemented, run them as an AI enrichment/indexing concern, not as a hard
requirement inside document ingestion.

Provider expectations:

- Use provider-neutral interfaces for generative calls.
- Keep provider config separate from parser config.
- Surface failures as index/enrichment failures, not document ingestion
  failures.

### 4. Retrieval Contract

Hybrid retrieval should combine full-text results with active-index vector
results when an active embedding index exists. The response should include the
citation payload needed by the frontend:

- document id and chunk id
- document name
- snippet or chunk content
- page range
- bounding boxes
- original text where available
- table or image asset references
- retrieval score and source

When no active embedding index exists, the same route should return full-text
results with citation metadata only.

### 5. Streaming Routes

Add authenticated routes for original files, rendered page images, and chunk
assets only after the provenance and asset schema are in place.

Suggested routes:

- `GET /vaults/:vaultId/documents/:documentId/file`
- `GET /vaults/:vaultId/documents/:documentId/page/:pageNumber.png`
- `GET /vaults/:vaultId/chunks/:chunkId/assets/:assetId`

Each route must enforce vault membership and document deletion state.

## Testing Expectations

- Unit-test parser provenance mapping, chunk asset persistence, and retrieval
  mapping.
- Integration-test migration shape for any new provenance or asset tables.
- Test authorization boundaries for file, page, and asset streaming routes.
- Mock AI providers in tests. Do not require live Ollama or live cloud services
  in CI.
- Verify ingestion still succeeds when no AI provider is configured.

## Explicit Non-Goals

- Reintroducing ingestion-time embeddings.
- Reintroducing `document_chunks.embedding`.
- Making Ollama mandatory for uploads, parsing, full-text search, or document
  management.
- Adding a second vector database.
- Coupling chat model changes to embedding index rebuilds.
